# Architecture Overview: 60Haus

This document outlines the high-level architecture, module boundaries, data flow, and key technical decisions powering 60Haus.

## 1. Feature Modules (Domain Driven Design)
The application is structured into isolated feature modules located in `src/features/`. Each feature encapsulates its own components, hooks, and services.

- **`discovery/`**: The core search and browsing experience. Includes `PropertyFeed`, map exploration, and search filters.
- **`communication/`**: The real-time messaging layer. Powers the unified Inbox, Chat threads, and Lead Management.
- **`analytics/`**: The Owner Dashboard insights engine. Computes and visualizes Views, Saves, Conversions, and Listing Health metrics.
- **`permissions/`**: Centralized privacy controls. Handles unified requests for location, camera, and notifications gracefully.
- **`platform/`**: The foundational operational layer. Houses `ErrorBoundary`, persistent offline queues (`retryQueueService`), logging, and network awareness.

## 2. Service Layer & Data Flow
All external API and database interactions are completely abstracted away from React components through single-responsibility Services (e.g., `propertyService`, `trustService`, `conversationService`).

### The Flow:
1. **Components** invoke custom Hooks (`useProperties`, `useAnalytics`).
2. **Hooks** manage React state, UI feedback (loading spinners, toasts), and coordinate with the Service layer.
3. **Services** execute raw data fetching (Supabase), formatting, and cache management.
4. **Platform Services** (`loggingService`, `connectivityService`) monitor the process silently.

## 3. Data Integrity & Trust Infrastructure
60Haus is built to solve trust deficits in real estate.
- **`trustService.ts`**: Aggregates verification vectors (Title Deeds, Owner ID, On-site Inspections).
- **Listing Quality Report**: An automated score generated by `insightEngine.ts` that penalizes stale or unverified listings.
- **Row Level Security (RLS)**: Enforced aggressively at the database layer. No client can bypass the permission rules defined in Postgres.

## 4. Offline & Resilience
- **Offline Banner**: Powered by `expo-network`, instantly warns users of lost connectivity.
- **Generic Retry Queue**: Failed mutations (e.g. sending a message) are pushed into an AsyncStorage queue via `retryQueueService`.
- When connectivity returns, the queue is processed with exponential backoff and optimistic UI updates are permanently synchronized.
- **Error Boundaries**: Hard crashes are trapped by the global `ErrorBoundary`, replacing the white-screen-of-death with a friendly recovery prompt.

## 5. Performance Strategy
- **Memoization**: Heavy components (Maps, Discovery Feed) leverage `React.memo` and `useCallback`.
- **Custom Visualizations**: Analytics charts are built ground-up using `react-native-svg` and `react-native-reanimated` to run entirely on the UI thread, bypassing heavy chart libraries.
- **Pagination**: All endless lists employ Supabase's range limits and FlashList for 60fps scrolling.
